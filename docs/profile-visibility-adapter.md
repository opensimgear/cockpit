# Native profile visibility and enable overrides

`profile_session_visibility::Visibility` composes the existing controller visibility owner, worker and persistent compare-fenced recovery journal. It never opens another input handle or writes HidHide directly. Current visibility qualification gates remain closed; tests do not qualify physical hiding or a broader visibility scope.

`prepare(plan, snapshot, owner, io)` is read-only. Hidden selections must resolve through explicit local assignments to one exact live native physical HID instance each, with a current capture baseline. Up to sixteen physical instances share one policy session. Portable `hidden-while-active` intent captures each selected device's explicitly saved local hide policy, including its chosen executable path when applicable. It cannot invent HideAll, unhide external devices or substitute Unix input suppression for HidHide. Existing native preflight checks feature enablement, qualification, exact global-policy representability and recovery conflicts.

`receipts()` returns one native recovery reference before any mutation. It pins the full profile run owner, a fresh visibility-owner UUID, exact physical controller IDs and preparation hash. It contains no Apply policy, executable path or replayable mutation. The native controller service owns the detailed journal.

After acquisition and genuine baselines, `start()` submits the retained preparation once. An ambiguous or failed Start cannot be retried. `poll()` checks exact job and active journal identities; early termination or attention prevents profile delivery. `stop()` cancels the existing owner, then polls its asynchronous restoration and releases that owner only after restoration succeeds. The Host must wait for `Progress::Active` before arming delivery and `Progress::Restored` before considering cleanup complete.

`from_receipts(run, io)` creates cleanup authority for the exact retained owner. It has no preparation and cannot Start. Recovery uses only guarded native Stop/restore; it never rehides devices or replays profile input. The existing journal compares current state with its still-owned expected state before reversing one field at a time. External changes remain preserved as recovery conflicts. Another native visibility owner is never displaced.

Temporary controller enable intent is separately validated by `profile_session_overrides::validate`. It is explicitly unsupported on the current transports. Existing CAN Enable/Disable is an automatically saved remembered-controller lifecycle operation, not a temporary runtime override. Direct USB firmware has no HID publication enable lease. A future adapter requires advertised nonpersistent publication ownership, exact gateway/module/connection/boot fencing, a captured prior state, a last-owned value, compare-if-unchanged restoration and explicit release/expiry. No profile adapter writes permanent firmware settings to simulate this capability.
