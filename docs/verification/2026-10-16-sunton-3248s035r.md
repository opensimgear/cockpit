# Sunton ESP32-3248S035R support — 2026-10-16

The user's yellow 3.5-inch ESP32 board photos match the ESP32-3248S035R resistive-touch layout. Added an explicit board profile rather than guessing from USB VID/PID. Identification is based on the photos and board-family documentation; physical USB flashing, pairing and live delivery have now been exercised through Cockpit.

Implemented:
- Original ESP32 target, 4 MB DIO flash, no PSRAM.
- ST7796 RGB565 SPI display in 480×320 landscape, bounded 64-byte non-DMA FIFO transactions and no full-frame allocation.
- XPT2046 on the same SPI2 bus, median samples, pressure filtering, configurable raw calibration limits, landscape rotation, release and I/O-failure handling.
- Exact profile/MCU installation choice in Cockpit, with ESP32 bootloader offset 0x1000 and retained ESP32-S3 offset 0x0.
- Firmware staging accepts only known board/MCU combinations.
- CI host driver test and pinned IDF Sunton cross-build/package artifact job.

Validation:
- ESP-IDF v5.5.2 Sunton firmware cross-build passed, including app and bootloader partition checks.
- App approximately 876 KB within 0x177000 app slot; static memory report is not a runtime Wi-Fi/TLS heap measurement.
- Host GCC ASan/UBSan tests passed for byte order, FIFO splitting, bounds, shared bus setup, touch transform/corners, release/pressure threshold, invalid ADC, mutex timeout and SPI failure.
- Companion serial Rust suite: 11 passed, including rejection of mixed ESP32/ESP32-S3 bootloader offsets.
- Existing Waveshare driver fault/coverage suite passed.
- Windows native Cockpit rebuild includes both firmware packages and was restarted.

Physical test on Windows COM6 (CH340), original ESP32-D0WD-V3 revision 3.1, 4 MB:
- Full original flash backup saved privately under ignored .research/sunton-device before installation.
- Reproduced selection clearing when another USB companion was already paired; selection now checks only the selected port. Pairing completion is bound to a new matching companion identity.
- Manual BOOT/RESET instructions and a skip-reset checkbox added beside installation.
- Removed the pre-flash UART identity re-probe; flashing revalidates the inspected candidate against current USB metadata. Auto-detection excludes listed setup candidates to preserve manual download mode.
- Original ESP32 uses read-only security eFuse checks because GET_SECURITY_INFO is unsupported. Secured boards remain rejected; S3 retains its existing security command.
- Flash failures persist until explicit retry instead of being cleared by background reconnection.
- Cockpit installed and verified all three bundled Sunton segments. Initial 921600-baud replies lost bytes on this CH340 adapter; the Sunton profile now uses 115200. Host setup and discovery detect both 115200 and the existing Waveshare 921600 rate.
- Completed the GUI wizard using Direct USB, name Sunton 3.5in, and existing Panel 1 (two widgets).
- Cockpit showed Connected, saved setup on screen, and Panel connected / touch ready with device state live-armed.
- Restarted native Cockpit after pairing; Sunton was remembered and automatically returned to Connected with Panel 1 without opening its setup wizard.
- Serial startup host tests pass at both configured baud rates.

The user confirmed readable display/colors/orientation, but reported that a top-left button registered at bottom-right. Reversed both touch axes for this landscape orientation and added explicit tests for all four corner mappings. Corrected firmware cross-build and ASan/UBSan host tests passed. Flashed the correction without erasing NVS, verified the flash hash, and restarted Cockpit; the existing pairing and assignment recovered. The user confirmed: "Touch is correct now".

Remaining qualification: detailed edge/corner calibration tolerance, long hold/release and disconnect cancellation under load, Wi-Fi provisioning on this no-PSRAM board, and runtime heap under network load. These were not claimed by this direct-USB test. The board profile README documents known calibration defaults and exact wiring.
