# Native profile companion adapter

The adapter consumes the retained native preparation proof and the saved profile graph. Capture allocates a fresh native ownership UUID per prepared run. Journaled acquisition installs the exact per-instance assignment receipt, then subscribes through the shared native companion provider. It does not read a global saved feedback route or create a legacy profile/role.

Real neutral baselines and exact native read/write tokens are required before Start. The Host must refresh the admitted native observation, bind the actual post-assignment delivery plan, capture another fresh baseline, and arm the adapter with the exact reducer run. Loss emits typed Disconnect frames for affected sources before timer advancement. Rebinding requires a new actual baseline; missing transitions are not replayed. Stop drops only this reader and clears only its exact owned feedback book; journal restoration handles assignments and shared connectivity remains installed.

Feedback uses the current reducer scalar state at no more than 30Hz. Known, Unknown, Stale and Unavailable remain distinct. Presentation derived by the graph is marked local; it cannot assert HID submission or game confirmation. A mismatched, inactive or frozen reducer run cannot renew widget freshness.

Six focused Windows native tests pass: empty Default has no companion setup side effects; actual baselines and delivery tokens are required; ordered native input and stale owner cleanup are fenced; unknown/stale/disconnected feedback remains truthful; malformed/unadvertised ports fail before effects; a feedback-only graph uses an actual panel session with no dummy graph source.

The current immutable publication/retained-provider contract requires 1–128 advertised interactive controls. A graph may use only feedback outputs from such a valid panel, but a publication with zero interactive controls is unsupported. No dummy control is added to bypass this contract.

Host takeover composition and renderer/physical companion acceptance remain separate verification. Native fixture results do not qualify live hardware or simulator output.
