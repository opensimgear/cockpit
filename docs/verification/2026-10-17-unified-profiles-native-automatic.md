# Native automatic profile selection

The desktop and gateway service start one background selector over the independent native game observer. It uses the normal one-use native profile Stage, fresh final admission, coordinator takeover and existing recovery journal. It never accepts executable paths, process IDs, process sessions, samples or resume authority from a browser rule request.

Rules persist in bounded versioned native settings. Manual selection remains pinned until an explicit Automatic choice. Pause, emergency Stop, recovery and faults inhibit selection. The highest enabled eligible game priority wins; equal highest priorities retain the current safe selection and report a conflict. With no matching game the target is Default. Failed or unchanged targets are not retried on every process poll; context or explicit operator changes permit a new attempt. Saving a profile revision does not replace an already applied snapshot.

Slow staging runs outside coordinator and admission locks. Final admission rechecks the policy epoch, pending operator controls, saved document and local assignments, native cancellation epoch and actual executable/process creation identity. A replacement process is rejected even before the cached watcher observes it. Stop first latches automatic inhibition and neutralizes native ownership; persistence cannot delay that revocation. Pending operator choices take priority over an automatic run prepared earlier.

Malformed optional automatic settings are preserved and disable automation. They do not prevent explicitly applying a healthy profile manually or returning to Default. Startup with unfinished recovery does not replay a saved graph. Recovery must complete explicitly before selection can resume.

- Ten focused tests passed against the actual native Manager, GamesRuntime and coordinator with deterministic platform fixtures, including external start/exit without any UI requests.
- Tests cover idempotence, saved revision isolation, ties, Manual pin, Pause, Stop, delayed staging, native process replacement, recovery, pending operator controls, malformed optional storage and background worker shutdown without an ownership cycle.
- Focused production coverage passed at 474/499 lines (94.99%) with unchanged native and portable source stamps. Default CI includes this module alongside all existing native module gates.
- Cockpit development stayed running on the main checkout throughout validation.

Hardware-first launch preparation is a separate verified unit. Actual Cockpit launch orchestration must preserve native ownership while waiting outside locks and must not start dormant game work with previously scheduled effects. Visibility composition, physical action dispatch and assembled Windows/game acceptance remain separate milestones. Existing output, script and HidHide qualification gates remain unchanged.
