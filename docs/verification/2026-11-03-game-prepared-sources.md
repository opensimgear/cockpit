# Prepared game artwork and car catalogues

Partial #188 / #194 implementation. Game artwork decoration now consumes an immutable runtime-owned image snapshot. Local file validation, hashing and image preparation belong to a separate source worker. Startup, committed metadata and discovery completion request preparation; native filesystem notifications invalidate changed sources. Getters never schedule that work or inspect files. Unrelated metadata edits reuse the existing image buffers when their exact source paths are unchanged.

The worker registers native watches before reading its baseline. Publication checks the exact captured catalogue, library revision, source generation and lifecycle. A delayed result cannot overwrite a newer scope or publish after close. Reads clone a shared snapshot handle under a short lock, then build JSON outside it. Managed sources are revalidated without the old global path cache so deletion or same-reference tampering cannot retain a falsely valid image. Existing manual/default/platform precedence, positions and crops remain intact.

The prepared library honors the existing 512-game bound, up to 1,024 managed references and 512 selected installation images, with existing per-image size limits. Matching image bytes share immutable buffers; retired snapshots retain buffers only while referenced. Exact generated file paths and their parent directories determine watch scope. No arbitrary external file path is exposed to consumers.

Native watches use pinned [notify 8.2.0](https://docs.rs/notify/8.2.0/notify/) `RecommendedWatcher`; polling and null backends are rejected explicitly. There is no polling fallback or periodic refresh. Bounds are 2,048 targets and 64 stable watch directories, with at most two registration sets during replacement. New registrations precede old-watch retirement. Missing parents use their nearest existing ancestor, and directory recreation rearms before the next baseline. Callbacks perform no filesystem access and clone immutable filter handles before matching. Access events and directory content/last-write notifications are filtered; relevant file changes, ancestor creation/deletion/rename, rescan markers and native errors request a new source baseline. Errors are bounded and visible; retries require a real source or committed change.

Installed-car persistence has a separate writer gate and immutable reader snapshot. Successful persistence publishes the new snapshot; validation or external revision failure retains the old one. Each setup operation has its own atomic publication token. Cancellation accepted before commit reservation preserves both durable payload and revision. Once reservation wins, cancellation returns an explicit “already finalizing” error promptly rather than waiting behind persistence or falsely acknowledging cancellation. A retired token cannot be reused by another operation.

Game metadata commits release the shared reader mutex before durable persistence while retaining serialized writer admission and repository revision checks. Readers see the previous committed snapshot during a write. Artwork collection also runs outside metadata admission and rereads durable authority under its existing cross-process asset lease.

## Remaining scope

This source preparation is a prerequisite for complete games projections, immutable paging and UI subscriptions; existing game UI and upstream process/context refresh intervals remain open. Wider command admission is not claimed migrated: setup cancellation can still wait behind other setup admission work, and application shutdown joins source I/O as part of lifecycle cleanup. Full adapter/device/companion/MCP cutover and integrated qualification remain open. Physical input-to-preview/output timing and actual simulator/board effects remain unqualified in #199, first in progress. Assetto sampling approval is unresolved. CI is deferred until all features are implemented, per user instruction.
