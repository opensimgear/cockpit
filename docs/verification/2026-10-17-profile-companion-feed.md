# Native companion profile feed

Unified profiles can subscribe directly to exact retained companion definitions and declared controls through the existing bounded native provider. The API creates no legacy mapping profile or role. Its descriptor projection is the same function used by actual SourceSink registration, including native integer axis ranges and declared fallback values.

Baseline capture discards pre-Start transitions and requires actual neutral current input. Loss and reconnect preserve source generation fences and isolate peers. Unchanged state renews only from actual native baseline/input/heartbeat observation time; calling poll does not manufacture freshness. Current-state renewal follows queued ordered transitions and cannot replay an event. Dropping a feed unsubscribes its reader without stopping shared transport.

Five focused tests cover exact contracts and bounds, real baseline requirements, held controls, pre-Start history discard, peer isolation, reconnect, native integer conversion, and real-heartbeat freshness. All 76 mapping-host tests pass, including retained native worker lifecycle tests. `scripts/mapping-host-coverage.py --output-dir .research/profile-companion-feed-coverage` passes all ten modules at the unchanged 71% minimum; the new native feed is 182/192 (94.79%). The runner accepts an explicit shared cargo target while retaining its default isolated target.

The profile Host adapter and actual renderer/physical companion acceptance remain separate work. These fixture tests grant no live hardware qualification.
