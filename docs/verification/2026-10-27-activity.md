# Persisted Activity acceptance — 27 October 2026

Activity now records native operations and background changes independently of
the selected UI page. SQLite owns event history, full-text search and retention.
The default retention is seven days. The UI provides compact expandable rows,
search, time/category/severity/type/entity filters, stable older pages, and a
confirmed clear-all action. The same operations are available through MCP.

Verified locally:

- All 1,250 frontend regression tests passed; the additional Activity transport
  lane test and affected model/transport tests passed afterward.
- Svelte checks and production UI builds passed, including a source snapshot
  containing only the Activity changes and their existing HEAD dependencies.
- Broader native regression: 1,412 passed, 11 ignored, zero failed, with the
  pinned DCS-BIOS archive and access to local sockets and temporary files.
- Final Activity source snapshot: 17 selected native tests passed, including
  background serial discovery, cached module availability, profile edits made
  without UI commands, lifecycle changes, retry batching, and MCP authorization.
- Persistence: all 44 tests passed. A passive `open_existing` does not install
  tables or change backup bytes; ordinary startup installs the current Activity
  tables while preserving existing records.
- Frontend Activity model coverage: 100% lines/functions, 95.77% branches.
- Native Activity line coverage per module: runtime 97.96%, audit 100%, capture
  100%, writer 93.88%, session 100%, gateway 96.67%, games 100%, integration 100%.
- SQLite Activity line coverage: storage 97.22%, queries 98.54%.

`tests/ui/activity-native.mjs` passed against the actual desktop Cockpit using a
fresh isolated database. It verified game and profile changes, activation/stop,
UI reload persistence, expandable compact rows, full-text search, combined
filters, retention settings, pagination past 100 events, clear-all cancellation
and deletion, and actual MCP discovery/settings/search/idempotent clear replay.
The test verifies the native database path before touching generated test data.

Provider observations determine device/game availability; the native collector

The availability test uses a native collector with controlled discovery and
cached adapter observations; a physical unplug was not required for this change.

## Inventory-cache noise correction

The running Cockpit initially contained 401 automatic `remembered` preference
saves among 421 events. These three-second cache writes crowded meaningful
activity off the newest page. They no longer create events; existing successful
cache-save rows are excluded from history/search/facets without deletion.
Explicit device Forget actions and cache-storage failures remain logged.

Verified with 19 focused Activity tests, 9 native preference tests and all 45
persistence tests. Changed native modules have 96.67–100% line coverage; Activity
query coverage is 97.08%. In the actual Cockpit, inventory cache revisions
advanced from 42825 to 42827 while the stored bookkeeping count stayed unchanged.
A temporary profile's create and rename events appeared in the compact list;
the verification profile was then removed without changing runtime ownership.
