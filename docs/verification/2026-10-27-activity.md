# Persisted Activity acceptance — 27 October 2026

Activity now records native operations and background changes independently of
the selected UI page. SQLite owns event history, full-text search and retention.
The default retention is seven days. The UI provides compact expandable rows,
search, time/category/severity/type/entity filters, stable older pages, and a
confirmed clear-all action. The same operations are available through MCP.

## Inventory-cache noise correction

The running Cockpit initially contained 401 automatic `remembered` preference
saves among 421 events. These three-second cache writes crowded meaningful
activity off the newest page. They no longer create events; existing successful
cache-save rows are excluded from history/search/facets without deletion.
Explicit device Forget actions and cache-storage failures remain logged.

Verified with 19 focused Activity tests, 9 native preference tests and all 45
persistence tests. Changed native modules have 96.67–100% line coverage; Activity
query coverage is 97.08%. In the actual Cockpit, inventory cache revisions
advanced from 42825 to 42827 while the stored bookkeeping count stayed unchanged.
A temporary profile's create and rename events appeared in the compact list;
the verification profile was then removed without changing runtime ownership.

## Readable changes and failure reasons

Verified against the normal database in the running native dev Cockpit. A
temporary profile was renamed, given a processing node, and edited again. Its
expanded Activity row showed both `Factor: 10.0 → 17.0` and the corresponding
output-range change. A stale rename showed the exact native rejection,
`Profile revision conflict: expected 1, current 4.` Full-text search found the
numeric change. The temporary profile was removed and runtime ownership was
unchanged. The compact preview and expanded details were visually inspected.

Profile snapshots are captured with their database transaction, so concurrent
edits retain their own old and new values. Slow native application yields to a
newer save and emergency controls. Private audit snapshots are removed before
responses reach UI/MCP clients. Cancellation auditing uses nonblocking status
observation rather than waiting behind takeover locks.
