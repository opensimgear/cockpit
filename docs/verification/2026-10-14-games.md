toolchain, the normal Cockpit native manager and independently running production
C gateway/peripheral simulations. PCB versions remain 0.1.0.

## Production simulation acceptance

`tests/e2e/games-acceptance.mjs` passes using the normal Rust service and production
C gateway and pedals processes. It verifies a captured name/axis-neutral override,
controller disable/unpublish, no device flash save, blocked conflicting manual
configuration, full configuration/controller publication restoration, previous
unconfigured integration restoration, and profile/default/manual-discovery
persistence after restarting Cockpit without automatic activation.

The installation fixture is an authored file named `DCS.exe`; **Activate profile**
never executes it. The scenario is part of the repository's ordinary E2E runner.
The existing full E2E collection was not rerun during this change.

## Browser verification

The isolated development browser uses the normal native API to verify initial
found-only filtering, the top-right supported-game switch, muted missing tiles,
missing-game details, activation/launch guards, default-profile deletion guards
and creation/persistence of a named profile.

An interception-only installed-game fixture verifies that Launch starts hidden,
appears on hover and keyboard focus, and Enter sends the correct game's default
profile in `game_launch`. That check does not spawn a game process. Browser
artifacts, native profiles and coverage reports remain under the workspace's
`.research/` directory.

Installed Windows DCS/Steam/Rally launch, live game telemetry and physical USB,
LED/display and CAN behavior still require live qualification. Simulation and
unit-test results do not establish those hardware/game outcomes.
