# STM32 gateway / generic device / Cockpit integration

This records the earlier private CAN v2 integration. The subsequent Cyphal
migration replaces that device/gateway wire transport and reports
`canProtocol=3`, retaining CDC v2 and the same registry/HID semantics. Cockpit
accepts both versions; current transport tests and build instructions live in
the [protocol repository](https://github.com/opensimgear/protocol). The historical
UI/package checks below were not repeated as part of the transport migration.

Source integration completed on 2026-10-12. The generic device now announces its
stable identity and profile over normal CAN FD, accepts gateway assignment and
publishes acquired inputs without USB connected. The gateway discovers modules,
maintains pending/active registries, generates HID and exposes correlated CDC
snapshots. Cockpit desktop discovers the physical gateway and presents devices,
pending registration and explicit Apply layout. The Pico simulator is preserved.

## Verified in software

- Generic firmware native input/client tests pass with address/undefined behavior
  sanitizers. Full profiles use the identical CAN v2 codec; all three profiles
  cross-build with Arm GCC 14.3. Boot counters reserve persistent journal state;
  SRAM is restricted to the guaranteed 128 KiB and application flash to 124 KiB.
- Gateway native core/journal tests pass with sanitizers. Tests cover descriptor
  bounds128 buttons/four hats/eight axes, legacy registry upgrading, interrupted
  storage, session/lease/generation guards and actual HID completion snapshots.
- 35 Rust tests pass serially, including partial serial reads, incompatible or
  oversized frames, stale correlation IDs/epochs, direct ownership, offline
  neutralization, UID-based reconnection and lost Apply acknowledgements.
- 24 frontend transport/discovery/guide tests pass. Svelte validation reports
  zero errors/warnings and the official autofixer reports no issues. Vite builds
  successfully.
- The macOS release app and DMG both build successfully. Disk-image packaging
  requires macOS disk-image operations outside the restricted sandbox. No
  gateway/device firmware was flashed and the new app was not launched against
  physical STM32 hardware.
- A real browser used C-generated snapshots to exercise **discovery → Add
  controller → Apply layout → read-only live view** at maximum capabilities.
  Screenshot, accessibility snapshot and mock runner are retained locally under
  ignored `output/playwright/`. The network response was simulated; this check
  does not establish physical USB/CAN behavior.
- `protocol/tools/verify_can_vendors.py` verifies six codec files and the shared
  gateway/Cockpit fixture copies against canonical snapshots and fresh C output.
- The sanitized cross-firmware test links the actual gateway and generic client
  with pinned common acquisition code. It drives contacts, hats, ADC samples and
  an encoder through encoded discovery/assignment, registry persistence, HID
  completion ACK and delivery. Ownership, stale lease/ACK and retained offline
  slot checks pass. Run `python3 protocol/tests/run_gateway_generic.py
  --workspace /path/to/opensimgear --sanitize` from the workspace; dependencies
  remain under `.research` and no hardware is flashed.

The private v2 transport is not Cyphal and is incompatible with older v1 peers.
Update both firmwares together. CDC mutations are guarded by the gateway epoch;
Apply saves first and reconnects once. The adapter inspects the returned registry
after a lost acknowledgement instead of repeating an ambiguous write. Offline
controllers remain neutral and keep their assigned report ID.

## Physical acceptance still required

Use actual gateway and generic-device boards, legitimate assigned USB IDs and
the documented current-limited 12 V supply. Connect continuity-verified 4P4C cables
(1=12V,2=CAN_H,3=CAN_L,4=GND) on one linear chain with two endpoint terminators.
The gateway sockets are parallel ports on that chain. Use compatible v2 builds.

Verify discovery on CAN-only power; Add/Apply and independent OS HID enumeration;
buttons/hats/axes and encoder press/release delivery; module unplug/replug with
unchanged slots; gateway reboot restoring registration; direct USB takeover and
fresh-input rearming on return to CAN; USB suspend/resume; changed profiles;
missing terminators/bus-off recovery; simultaneous announcements and maximum
chain load. Observe actual electrical waveforms, rail temperatures/current and
USB descriptors rather than relying solely on Cockpit state. Repeat serial/HID
acceptance on Windows/Linux before claiming platform support.

## Remaining scope

Device profiles/calibration are compiled into firmware. Device settings writes,
output sessions, firmware update/recovery UI, simultaneous inventories across
multiple gateways, cross-chain duplicate-identity diagnostics and the canonical
production protocol are future work. This integration manages one selected
gateway and up to 10 retained controller slots. One HID interface uses a separate
report ID/top-level collection per occupied slot; host game bindings may need
review after an explicit layout change.
