# Native controller publication transport

The CAN gateway adapter now recognizes the exact nonpersistent publication
capability and bounded status/module metadata. It keeps configured enable state
separate from actual HID publication. Unknown capabilities stay unsupported;
only validated targeted ownership can explain a settled publication overlay.
Pico and direct USB acquire no authority from these fields.

A native typed request shares the existing serial owner and configuration writer
gate. There is no browser JSON command that accepts a publication owner. Claim
and Renew require both a live native run latch and its current control epoch,
checked again immediately before the serial write. Obsolete unsent work leaves
the replacement transport open. Mutations are sent once. Reconnect uses exact
gateway identity and read-only snapshots, followed by request-scoped private-owner
inspection; its proof and state come from the same correlated reply. Private
owners and ownership probes are absent from the UI cache.

Local injected transport verification passed all 62 Stm32 cases and seven shared
native panel-dispatch cases. The conformance fixture was generated by production
gateway C, covering configured, temporarily hidden, privately inspected and
restored snapshots. Tests also cover foreign ownership, malformed metadata,
temporary enable of a configured-disabled controller, revoked delivery, lost
mutation replies, queue/epoch fencing and unsupported JSON/transport paths.

Source-stamped focused coverage in `.research/publication-worker-coverage`:
`stm32_publication` 92/92 production lines (100%); shared panel dispatch 192/197
(97.46%). Both exceed the unchanged 71% per-module gate, and the new module is
included in CI's default coverage list. This transport evidence uses injected
serial connections. It does not establish profile Host composition, physical
USB enumeration, Windows/game behavior, or any live qualification.
