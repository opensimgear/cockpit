# Native hardware-first launch context — 2026-10-17

The native Host now supports the coordinator's journaled hold after acquisition, genuine baselines and visibility but before Start. It keeps the same hardware run owner and restoration receipts. Held health renews the acquired output, checks visibility ownership, drains native hardware input and validates owned companion baselines. No reducer exists, so no timer, script callback, queued graph input or action effect can acquire pre-start authority.

The exact post-commit cancellation epoch is bound once. At that boundary the Host captures actual acquired hardware delivery identities, including a companion's newly acquired publication B rather than its original prospective publication pin. A changed native route, provider session, generation, capability or contract blocks completion. Stop or Pause changes the epoch before waiting for the transition lock; a late stage cannot install its owner.

`NativeProfileHost::stage_launch_context` consumes the launch helper's native StartedGame. The helper revalidates the current installation and exact process identity. Off-lock preparation may acquire an actual read-only game source and await advancing telemetry; it never reacquires hardware, reassigns companion panels, preflights active visibility or starts graph work. The private Stage is one-use and bound to the saved document, local assignments, selected context and cancellation epoch.

Provider setup is optional. A hardware-only selection or an unavailable optional provider completes with no game child and dormant integration branches. Process verification is independent and remains required. Native priority policy may select another already running game; the requested spawn and selected provider are independently verified, and only the selected context receives a child owner. When that provider is ready, the Host refreshes native baselines, then starts the reducer for the first time. It never edits the hardware RunOwner. Stop explicitly revokes the child even when the hardware owner itself has no game ID.
