# Downloadable companion scenes: implementation and hardware record

This record extends the [foundation checkpoint](2026-10-16-foundation.md) and the [complete plan](../../companion-render-packages.md). GitHub tracks [R2](https://github.com/opensimgear/cockpit/issues/72), [R3](https://github.com/opensimgear/cockpit/issues/73) and [physical qualification R6](https://github.com/opensimgear/cockpit/issues/76). Implementation is in draft [PR #77](https://github.com/opensimgear/cockpit/pull/77).

## Implemented path

The pure TypeScript compiler lowers a native validated source publication and resolved visual recipe into an exact canonical manifest plus OSGC semantics, OSGS scene, OSGI image and OSGF font objects. The original A/B starter panels are independent compositions for each screen. B adds a composite and different artwork/bindings without adding a firmware widget type. Bundled Rajdhani fonts carry their OFL license; Python font preparation is a development step.

The native host compares every compiled semantic control/output with the trusted source. An authenticated device negotiates its exact profile hash, prepares an assigned package and reads at most 2,048 decoded bytes at a time. Preparation creates no input source. The device streams to inactive raw flash, verifies all hashes, canonical metadata, binary structure, references and resource bounds, then commits its journal marker last. Offline boot restores verified content, never an armed state. Host disk selections are also restored only after source revalidation; eviction protects active and prepared packages.

After successful presentation, `render-open` rechecks source/package/profile/descriptor identities and creates a fresh disarmed session. Existing neutral baseline, source ownership and hard input leases remain in force. Normal traffic uses bounded compact typed feedback, not graphics or layout commands. USB and real pinned WSS tests exercise the same host management boundary. Main renders eight tiles per slice; touch sees an immutable hit cache published after the display fence. Navigation stops input and obtains a new session.

## Device budgets

| Item | Sunton ESP32-3248S035R | Waveshare ESP32-S3-Touch-LCD7 V1.2 |
| --- | ---: | ---: |
| Screen | 480 × 320, ST7796 shared SPI | 800 × 480, RGB framebuffer |
| PSRAM required by renderer | 0 | 0 for this implementation |
| Renderer internal allowance | 24,576 B | 32,768 B |
| Conservative engine + work + adapter minimum | 22,232 B | 26,328 B |
| Package ceiling | 768 KiB | 2.5 MiB |
| Manifest capacity | 4 KiB | 8 KiB |
| Raw `ui_store` at `0x190000` | 2 MiB | 6 MiB |
| App at `0x10000` | 1.5 MiB | 1.5 MiB |
| Existing main / network stacks | 8 KiB / 24 KiB | 8 KiB / 24 KiB |

These allowances describe the added renderer. Existing logical images, transport buffers, task stacks and bounded temporary JSON allocation remain device-wide costs. See [engine accounting](../../../apps/companion-esp32/render/ENGINE.md). Exact target stack reports show the principal update chain at 3,088 B before flash/SDK frames; hardware high-water measurements remain necessary.

The initial native adapter supports momentary controls, navigation and boolean/numeric outputs. Its logical shim permits 32 total controls plus outputs. Numeric source endpoints must be exactly representable in Q16.16; 0.1–0.9 is rejected explicitly, while 0.5–99.5 is supported. Arbitrary text feedback, complex input/XY/triangle controls and designer UI publication are subsequent qualification/integration work. Widgets are qualified per profile; compatibility across all screens is not required.

## First physical Waveshare run

The engine installer wrote only bootloader/table/application at offsets `0`, `0x8000`, `0x10000`. It validated the existing partition table and security state first, verified all three written ranges with SHA-256 readback, and checked NVS/PHY integrity on-device before and after. No raw NVS backup or eFuse write was made.

Both A and B reached `live-armed` through the production USB manager, with host-accepted synthetic numeric/indicator feedback. Input source loss occurred on assignment replacement before the second package download. A read-only full application readback after A → B matched the installation exactly:

`006a5f180476b37a543108b3106c3bd23fa278efa99f2a36e70c5d1993bafef6` (942,448 bytes).

This establishes the unchanged-firmware package swap for that run. It does not establish a stable soak. B later lost its connection; the initial log omitted the existing device fault-status field, so the exact physical cause cannot be asserted from that trace. The run also exposed a deterministic same-package warm-presentation bug: a replaced logical shim with unchanged scene pixels did not trigger the new readiness fence. A regression-tested fix now presents trusted chrome once for that activation without redrawing valid scene pixels.

A separate deterministic UART ownership defect was found during investigation: the outer command parser could retain a prefix at EOF and then let the synchronous reply parser consume its suffix. The fix retains parser ownership until newline; an armed fragment stalled for 100 ms cancels input without renewing its ACK lease, and poisoned suffixes are discarded until newline. Native fragmented/timeout/held-source regressions pass. The defect is consistent with the initial immediate disconnect, but the old physical log cannot prove that cause. The corrected engine is being checked on both boards before stable results are recorded.

## Reproduction and remaining qualification

Build both firmware profiles with `tools/idf.sh` and fresh profile build directories. The one-time helper is `cargo run --locked --manifest-path crates/companion-serial/Cargo.toml --example install-render-engine -- PORT PROFILE BUILD_DIRECTORY EVIDENCE_DIRECTORY`; Sunton may require `--manual-boot`. `--read-only` performs no firmware writes. Unknown flags, incompatible layouts, extra partitions and checksum failures reject before writes.

Use `cargo run --locked --manifest-path crates/companion-serial/Cargo.toml --example render-poc -- --state-dir DIRECTORY --sunton COM6 --waveshare COM5 --seconds 300 --switch-after 20` for a bench A → B run. DIRECTORY supplies protected host state read-only; the helper copies it into its own `render-poc-run` child. It uses a recording sink and explicitly host-accepted synthetic feedback, not a game integration. `--revision B --reuse-packages` exercises persistent host/device cache reuse. The proof runner logs only whitelisted state and counters.

Sunton physical engine installation is waiting for manual BOOT/RESET entry. Stable repeated/warm tests, device byte/timing measurements, physical visuals/touch, Wi-Fi/WSS, long soaks and physical power cuts remain open in R6. Automated power-cut tests do not replace that hardware evidence.
