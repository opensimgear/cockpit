# Profile physical action worker

`PanelActions` composes the exact native endpoint lease primitive on bounded workers. It does not open a transport, use browser-owned route tokens, create a second journal, or change platform qualification. Preparation checks the immutable compiled physical sinks and produces the existing sealed per-endpoint receipts without claiming output. Required unsupported outputs block preparation; optional unsupported outputs are reported by `optional_unavailable()`. Supported anticipated endpoints on dormant branches are sealed into the original manifest but have no worker or claim. Required unsupported anticipated endpoints block preparation. Before Start, verified launch Baseline may call `acquire_ready(fresh_plan)` once to activate an originally sealed endpoint whose branch is now Ready; the immutable program and receipts stay unchanged. Unsealed optional endpoints remain unavailable until a fresh Apply. Duplicate native endpoint aliases and more than 16 endpoints are rejected.

The native Host integration sequence is:

1. `prepare(plan, owner, resources, panel_io)`, then add `capture_receipts()` to the coordinator manifest before acquisition.
2. `acquire()` starts bounded workers without waiting for serial I/O. `poll().acquired` reports completion. Each endpoint claims once through `claim_current`.
3. After claims, bind actual hardware Invoke tokens promptly (inputs and game commands may still await baselines) so neutral leases can renew. At Baseline, `acquire_ready(fresh_plan)` admits only originally sealed dormant endpoints before Start; `bind_delivery(fresh_plan)` queues the exact fresh native Invoke tokens; it returns whether all required endpoints are bound. Binding is checked on the owner worker, followed by a guarded renewal. A changed real token may be rebound before Start only; the same exact endpoint lease is renewed, never reclaimed. A failed rebind revokes output and proceeds to guarded cleanup. `start()` permits effects only once those bindings have succeeded.
4. `dispatch(&effects)` receives the whole drained typed-effect batch. It pre-revokes every endpoint with a known loss before admitting earlier tuples. `poll()` reads cached status and diagnostics; neither method performs transport I/O.
5. `stop()` immediately stops acceptance, clears queues and wakes workers. It returns pending until existing bounded operations finish and token-fenced release completes. The coordinator must retain receipts while `cleanup_complete` is false. A failed cleanup is reported, not silently marked restored.

A process-wide 16-worker budget covers retiring runs too. Each endpoint has a 64-entry FIFO; known action tuples are checked for exact names, order, scalar bounds and at most four arguments before copying into that queue. One-shot events are never coalesced. Every effect must match the native run, exact compiled sink, increasing sequence and monotonic effect time. Baseline and fallback cannot replay one-shot actions. The worker renews every second under the advertised five-second lease; no UI poll is required. Missing delivery binding expires the preparation after three seconds. Lease or delivery failure revokes that endpoint and discards its queued work. It is not automatically reclaimed when inputs reconnect.

An accepted request already in flight may finish after Stop or source loss. The same worker then releases that lease through firmware's compare-if-unchanged restoration; no later queued request may run. Independent endpoint workers continue while an affected endpoint is stopped. Overflows and invalid tuples revoke their endpoint. Required failures are surfaced through `ActionPoll.required_failed`; optional failures remain diagnostics.

`recover(owned_run, resources, panel_io)` creates cleanup-only actors from existing sealed receipts. Calling `stop()` starts only inspection and guarded release. Recovery cannot bind delivery, claim, Start or invoke. It never reconstructs a command tuple from a graph. Changed or unavailable exact native routes remain unresolved for explicit recovery, as described by the lease primitive.

The worker is tested independently of device framing: FIFO/no coalescing, delayed claim cancellation, pre-loss queue suppression, independent endpoints, overflow, stale run/sequence/sink rejection, baseline one-shot suppression, no-output initial unknowns, autonomous renewal failure, optional admission, global worker limits and unresolved cleanup. The lower-level USB/CAN lease tests separately exercise actual route/catalogue/argument and sealed-recovery contracts.

`NativeProfileHost` now composes the worker through a dedicated physical-action child. Owner-specific preparation seals supported endpoint receipts before takeover or any claim. Acquire waits for claims and promptly binds real hardware Invoke tokens while game/input baselines may still be pending. Baseline can activate only originally sealed dormant slots; final Start revalidates and, if needed, rebinds the same exact native token before enabling effects. A pending launch polls cached action status while neutral leases renew independently.

The Host passes each entire typed-effect batch to the actor before other dispatch consumes it. Physical branch loss remains a degradation for independent running branches. Neutralize immediately revokes actor acceptance; restoration does not finish and outgoing receipts cannot be retired while any endpoint cleanup is pending or failed. Discard retains an unfinished actor for native recovery rather than dropping its ownership handle. Recovery only inspects and releases the exact captured lease; it never claims or replays an action tuple.

Focused Host tests use the actual native registry, compiler and phase methods, substituting only the bounded serial driver with an isolated test probe. They cover neutral hold, Start, stale route rejection, immutable program checks, cancellation before claim, unacquired cleanup, exact receipt identity and failed cleanup retention. Firmware framing, capture-at-claim, sealed recovery and compare-if-unchanged restoration remain covered independently by the endpoint primitive and firmware suites. These tests do not assert physical hardware qualification.

An optional endpoint that loses its native delivery proof before Start is permanently revoked within that prepared run and released by the existing worker. Independent branches may still start; its original receipt remains owned until cleanup finishes. A later fresh token or game context cannot reclaim that endpoint. Required endpoint proof loss continues to block activation. Empty physical-action adapters perform no extra inventory capture.

The final source-stamped focused gate passes 10 native Host cases (229/264 production lines, 86.74%) and 17 worker cases (499/592, 84.29%). Evidence is retained in `.research/profile-actions-host-coverage`; both original 71% module thresholds are unchanged.
