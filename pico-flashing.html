OPENSIMGEAR · GATEWAY SIMULATOR

Flash your Pico W.

This firmware runs on the RP2040 Raspberry Pi Pico W. It exposes real USB joystick controllers while Cockpit simulates module inputs over USB serial. No Apple signing identity or GPIO wiring is needed.

Firmware 0.1.1 names the default modules OSG Sequential shifter, OSG Pedal set, OSG Button panel, and OSG Handbrake. Saved device names become USB interface labels after a gateway reconnect. On macOS, Cockpit also applies individual HID controller names; rescan or reopen apps that cached the old names.

Download gateway firmware (.uf2) SHA-256 checksum

In the desktop app, the download saves the bundled firmware to Downloads and shows its path. Copy that file onto RPI-RP2 to flash it. Developers: generate firmware with pnpm pico:build, then rebuild Cockpit to include the updated image. Flashing replaces the firmware currently on the Pico. This build targets Pico W with RP2040, rather than Pico 2 W.

1. Enter BOOTSEL and copy the firmware

  1. Unplug the Pico. Hold its BOOTSEL button while connecting it to the Mac with a micro-USB data cable.
  2. Release BOOTSEL when the RPI-RP2 drive appears in Finder.
  3. Copy osg-pico-gateway.uf2 onto RPI-RP2. The drive ejects and the Pico restarts automatically.

BOOTSEL is stored in ROM. Repeat these steps to recover or reflash the board.

2. Connect from Cockpit

  1. Switch to the main Cockpit window and select Pico W · USB.
  2. Refresh the USB ports, choose the Pico's /dev/tty.usbmodem… or /dev/cu.usbmodem… port, and click Connect Pico.
  3. Click Start gateway, select a module, and open Inputs. Test buttons and sliders using a HID monitor or your simulator.

If no port appears, check the data cable, leave BOOTSEL mode, and close other applications using the port. Cockpit accepts only firmware that identifies itself as an OpenSimGear Pico gateway.

3. Add and remove modules

Add device registers a pending module. Remove module neutralizes its old inputs and removes it from the inventory. Use Reconnect gateway to rebuild the actual USB HID layout, then Start gateway. End setup sessions first. Check game bindings after a layout change.

Up to eight modules can each expose 0–32 buttons and 0–6 axes, with at least one input. Offline modules retain neutral controller slots; removing the final module leaves USB serial available.

Settings and registration stay in RAM until reset or power loss. CAN and calibration are simulated. Stop/disconnect, lost serial access, or the firmware watchdog neutralize inputs. Physical HID enumeration and report delivery require verification after flashing.

Run, build, and verify

Full SDK, toolchain, protocol, and acceptance-test instructions are in cockpit/simulator/pico/README.md. From the cockpit directory:

pnpm dev
pnpm pico:build
pnpm pico:test
pnpm native:test
pnpm transport:test
pnpm pico:verify --watch --timeout 20

pnpm dev opens the desktop app after preparing its resources. Install the Tauri platform prerequisites and pinned Rust 1.90.0 toolchain for development. Use pnpm web:dev for the browser fallback.

The independent HID observer reports actual macOS devices and input events. One Pico USB serial is shared by its HID interfaces; match each interface number to the module inventory in Cockpit.
